## Arches Vue Components 1.1.0 Release Notes

### Dependency changes:
```
Python:
    Upgraded:
        arches: >=7.6.9 -> >=7.6.9,<7.7

    Added:
        None

    Removed:
        None


JavaScript:
    Upgraded:
        arches: archesproject/arches#stable/8.1.2 -> archesproject/arches#dev/7.6.x
        arches-dev-dependencies: archesproject/arches-dev-dependencies#stable/8.1.2 -> archesproject/arches-dev-dependencies#dev/7.6.x

    Added:
        None

    Removed:
        None
```

### Breaking Changes

- Drops support for Arches >= 8.0. This release targets Arches 7.6.x only. [#11](https://github.com/archesproject/arches-vue-components/pull/11)
- `pgtrigger` is no longer required. Remove it from your project's `INSTALLED_APPS`. [#11](https://github.com/archesproject/arches-vue-components/pull/11)
- Removed the Arches-core-version branching in `CardXNodeXWidgetView`, `RelatableResourcesView`, and `CardNodeWidgetConfigMixin` — these views now assume Arches 7.6 model semantics. [#11](https://github.com/archesproject/arches-vue-components/pull/11)
- `MapDataAPI` now filters resource graphs by `graph__publication__isnull=False` instead of `graph__is_active` / `graph__source_identifier__isnull`, matching Arches 7.6's publication model. [#11](https://github.com/archesproject/arches-vue-components/pull/11)

### Bug Fixes

- Fixes `createVueApplication` to import `generate-arches-url` and `themes` via complete file paths, fixing module resolution under Arches 7.6's build. [#7](https://github.com/archesproject/arches-vue-components/pull/7)
- Fixes the frontend i18n bootstrap to request the `api_get_frontend_i18n_data` URL name used by Arches 7.6. [#7](https://github.com/archesproject/arches-vue-components/pull/7)
- Rewrites `generateArchesURL` to read routes from `.arches-urls` DOM attributes at runtime instead of the removed global `ARCHES_URLS` object, supporting both static string routes and route-generating functions with positional arguments. [#11](https://github.com/archesproject/arches-vue-components/pull/11)
- Calls `generate_frontend_configuration()` from `AppConfig.ready()` when this app is the project's root app, matching Arches 7.6's frontend-configuration bootstrap. [#11](https://github.com/archesproject/arches-vue-components/pull/11)
- Reads webpack, tsconfig, and vitest configuration from `.frontend-configuration-settings.json` / `.tsconfig-paths.json` (Arches 7.6's generated file names) instead of the `frontend_configuration/` directory. [#11](https://github.com/archesproject/arches-vue-components/pull/11)
- Fixes migration `0005_add_language_widget_mapping`, which depended on a core Arches migration that was never released, blocking installs against Arches 7.6.x. [#11](https://github.com/archesproject/arches-vue-components/pull/11)
- Fixes the `validate` management command's import of `VALIDATE` (previously `CommandModes`) and restores the `--codes` argument, both broken by an upstream rename in Arches core. [#11](https://github.com/archesproject/arches-vue-components/pull/11)

### Upgrading Arches Vue Components

1. Upgrade the python package:
    ```
    pip install --upgrade arches-vue-components==1.1.0
    ```

2. Remove `pgtrigger` from your project's `INSTALLED_APPS`:
    ```python
    INSTALLED_APPS = (
        "my_project_name",
        ...
        "arches_querysets",
        "arches_vue_components",
        "arches",
        ...
    )
    ```

3. Update the frontend dependency in `package.json` and reinstall:
    ```
    npm install
    npm run build_development
    python manage.py collectstatic
    ```

4. If you are running Arches on Apache, restart your server:
    ```
    sudo service apache2 reload
    ```
